\# SmartRetail-X Database Architecture



\## 1. Overview



SmartRetail-X uses PostgreSQL as the primary relational database for storing, organizing, and querying retail transaction and analytical data.



The database provides a structured data layer between the data engineering pipeline and the machine learning and application layers.



Database name:



```text

smartretail\_x

```

\## 3. Database Schemas



The database is organized into separate schemas to provide clear separation of responsibilities.



\### raw



The `raw` schema is intended for raw or minimally transformed source data.



Purpose:



\* Preserve source-level information

\* Support data lineage

\* Provide a reference layer for ingestion



\---



\### staging



The `staging` schema contains cleaned and transformed transaction data before it is converted into the final analytical model.



Main table:



```text

staging.online\_retail\_transactions

```



This table contains the processed retail transaction dataset loaded from the feature engineering pipeline.



\---



\### analytics



The `analytics` schema contains the main business intelligence data model.



Tables:



```text

analytics.dim\_date

analytics.dim\_product

analytics.dim\_customer

analytics.fact\_sales

```



The schema follows a dimensional modeling approach.



\---



\### ml



The `ml` schema is reserved for machine learning related datasets and model-supporting data.



It can be extended with:



\* Forecast results

\* Model predictions

\* Model metadata

\* Feature datasets

\* Model evaluation results

The analytics schema uses a dimensional model consisting of dimension tables and a central fact table.




The `fact\_sales` table stores transaction-level business events.

\## 9. Transaction Types



SmartRetail-X distinguishes between sales and returns.



```text

SALE

RETURN

```



Negative quantities are classified as returns during data processing.



This distinction allows the analytical layer to separately evaluate sales activity and returned products.

\## 12. Database Loading Script



The main Python loader is:



```text

```



Its responsibilities include:



1\. Connecting to PostgreSQL.

2\. Loading the processed feature dataset.

3\. Creating or replacing the staging table as required.

4\. Loading transaction records.

5\. Preparing data for analytical table generation.

\## 14. Database Usage by Machine Learning

\## 18. Security Considerations



Database credentials are not stored directly in source code.



Sensitive configuration should be provided through environment variables or a local `.env` file.



Example:



```text

DATABASE\_HOST

DATABASE\_PORT

DATABASE\_NAME

DATABASE\_USER

DATABASE\_PASSWORD

```



The `.env` file must remain excluded from Git.



Database credentials should never be committed to the repository.
